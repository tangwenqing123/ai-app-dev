# 智能写作助手 – 完整项目文档（PRD + 技术设计 + AGENTS.md + 优化提示词模板）

> 本文档融合了产品需求、技术方案、开发规范以及基于30年编辑经验优化的6种写作模式提示词模板，供开发时直接使用。

---

## 一、产品需求文档（PRD）

### 项目概述
一款基于 React + TypeScript 的智能写作助手，调用 DeepSeek API 实现多种文本生成任务（续写、改写、扩展、总结、邮件撰写、营销文案生成）。用户可选择写作模式、调整创意度（temperature）和输出长度，支持流式输出、历史记录保存与查看。界面采用左右分栏布局，左侧为输入与参数控制区，右侧实时显示生成结果（支持 Markdown 渲染与代码高亮）。

### 核心功能

#### 1. 写作模式（6种）
- **文章续写**：基于用户提供的开头或片段，继续撰写连贯内容。
- **内容改写**：将用户输入的文本改写得更流畅、专业或适应特定风格。
- **内容扩展**：在用户输入的基础上增加更多细节、例子或论证。
- **内容总结**：提取用户输入的核心要点，生成简洁摘要。
- **邮件撰写**：根据用户给定的主题、收件人关系（正式/友好）生成完整邮件。
- **文案生成**：为产品生成营销文案，支持风格选择（如活泼、科技、高端等）。

#### 2. 输入与生成
- 左侧提供一个多行文本框（textarea），用户输入源文本或描述。
- 右侧实时显示 AI 生成的内容，采用**流式输出**（逐字显示）提升体验。
- 支持 **Markdown 格式**渲染（标题、列表、代码块、表格等），代码块需有语法高亮及复制按钮。

#### 3. 参数调节（高级设置）
- **创意度（Temperature）**：滑块范围 0～1，步长 0.1，默认 0.7。低值（0～0.3）适合事实性、确定性任务；高值（0.8～1.0）适合创意写作。
- **输出长度（Max Tokens）**：滑块范围 100～2000，步长 50，默认 800。
- 高级设置面板可折叠/展开，保持界面简洁。

#### 4. 辅助功能
- **优化提示词**：用户可以点击按钮，AI 会根据当前选择的写作模式和用户输入的内容，自动生成一个更详细、更有效的提示词（帮助用户学习如何更好地与 AI 交互）。
- **复制结果**：生成内容区右上角提供复制按钮，一键复制 AI 输出。
- **清空输入**：一键清空左侧输入框。

#### 5. 历史记录管理
- 每次生成（点击“生成内容”后）自动保存记录到 `localStorage`。
- 每条记录包含：生成时间、写作模式、用户输入、AI 输出结果。
- 左侧边栏（或右侧历史栏）显示历史记录列表，按时间倒序排列。
- 点击历史记录，可将该次生成的结果和输入加载到主界面（用于查看或重新生成）。
- 支持单条删除或“清空所有历史”。

### 非功能性需求
- 界面简洁现代，深色主题（背景 `#0a0a0a`，卡片 `#1e1e1e`）。
- 响应式布局：桌面端左右分栏（比例 40% / 60%），移动端切换为上下布局。
- 生成过程中禁用生成按钮并显示加载动画（“AI 正在写作…”）。
- 错误处理：API 调用失败、网络错误、参数无效等显示友好提示。
- API Key 通过环境变量管理（`VITE_DEEPSEEK_API_KEY`），严禁硬编码。

### 扩展思路（可选）
- 支持自定义提示词模板（用户可添加新模式）。
- 批量生成多版本（一次生成 3 个结果供选择）。
- 文本对比功能（对比不同参数或模式的输出）。
- 支持多语言翻译（在总结/改写时选择目标语言）。

### 核心实现要点

#### 1. 数据类型定义
```typescript
type WritingMode = 'continue' | 'rewrite' | 'expand' | 'summarize' | 'email' | 'copywriting';

interface GenerationRecord {
  id: string;           // timestamp + random
  mode: WritingMode;
  inputText: string;
  outputText: string;
  createdAt: number;
}

interface GenerateParams {
  temperature: number;
  maxTokens: number;
}
```

#### 2. API 调用（流式）
- 使用 DeepSeek API：`https://api.deepseek.com/v1/chat/completions`
- 请求体：
  ```json
  {
    "model": "deepseek-chat",
    "messages": [
      { "role": "system", "content": "你是一个专业的写作助手。" },
      { "role": "user", "content": finalPrompt }
    ],
    "stream": true,
    "temperature": temperature,
    "max_tokens": maxTokens
  }
  ```
- 使用 `fetch` 获取 `ReadableStream`，逐行解析 `data:` 前缀，累积 `delta.content`，实时更新输出面板。
- 注意处理 `[DONE]` 标记。

#### 3. 生成流程
1. 用户选择模式、输入文本、调整参数。
2. 点击“生成内容”按钮。
3. 调用 `promptTemplates` 生成完整提示词。
4. 创建一条占位记录（输出为空），添加到右侧显示。
5. 发起流式 API 请求，逐字追加内容。
6. 流结束后，将完整记录保存到历史（`useLocalStorage`）。

#### 4. “优化提示词”功能
- 点击按钮后，将当前用户输入和所选模式作为上下文，向 DeepSeek 发送一条特殊请求：`“请帮我优化以下提示词，使其更清晰、更有效：{原始提示词}。输出只需给出优化后的提示词文本。”`
- 然后将优化后的提示词回填到输入框中，供用户编辑或直接生成。

#### 5. 历史记录
- 使用 `useLocalStorage` 存储 `GenerationRecord[]`，键名 `writing-history`。
- 历史面板渲染列表，点击任一记录可恢复输入与输出（加载到主界面，不自动重新生成）。
- 删除功能：单条删除或全部清空。

#### 6. 参数保存
- 用户调整的 `temperature` 和 `maxTokens` 可选保存到 localStorage，下次加载时恢复。

### 环境变量
- 创建 `.env.local`：
  ```
  VITE_DEEPSEEK_API_KEY=YOUR_DEEPSEEK_API_KEY
  ```

### 响应式布局
- 使用 Tailwind `flex flex-col md:flex-row`。
- 左侧区域宽度 `md:w-2/5`，右侧 `md:w-3/5`。
- 历史面板在移动端可置于底部或通过汉堡菜单控制。

## 三、AGENTS.md（开发指令）

### 项目概述
开发一个基于 React + TypeScript + Vite + Tailwind CSS 的智能写作助手，调用 DeepSeek API 实现多种写作模式的流式文本生成，支持参数调节（temperature/max_tokens）、历史记录管理、Markdown 渲染及代码高亮。

### 开发规范
- 使用函数式组件 + Hooks，TypeScript 严格模式。
- 样式统一使用 Tailwind CSS，避免自定义 CSS。
- 组件拆分：`InputPanel`、`OutputPanel`、`HistoryPanel`、`ParameterControls` 等。
- API 调用统一封装在 `services/deepseekApi.ts`，支持流式响应。
- 提示词模板集中管理在 `services/promptTemplates.ts`。
- 所有用户配置（历史记录、参数偏好）使用 `localStorage`。
- 环境变量名以 `VITE_` 开头，API Key 不硬编码。
- 代码添加必要注释，特别是流式数据处理和错误恢复。

### 功能实现顺序（建议）
1. **初始化项目**：Vite + React + TypeScript + Tailwind CSS。
2. **安装依赖**：`react-markdown`、`react-syntax-highlighter`、`lucide-react` 等。
3. **定义类型**：`types/writing.ts` 定义 `WritingMode` 和 `GenerationRecord`。
4. **实现提示词模板**：在 `promptTemplates.ts` 中为 6 种模式编写函数。
5. **搭建基础 UI**：左右分栏布局，左侧包含模式下拉框、输入框、生成按钮；右侧显示占位内容。
6. **实现基础生成（非流式）**：先实现非流式调用验证流程。
7. **升级为流式生成**：实现 `useStreamingGeneration` 或直接在组件中处理流式数据，逐字显示。
8. **添加参数控制面板**：`temperature` 和 `max_tokens` 滑块，连接 API。
9. **实现历史记录**：使用 `useLocalStorage`，添加侧边栏显示列表，支持加载和删除。
10. **实现“优化提示词”**：调用 API 优化用户输入，回填到输入框。
11. **完善 Markdown 渲染与代码高亮**：在输出面板中使用 `react-markdown`，自定义代码块组件。
12. **增加复制按钮与加载状态**：提升用户体验。

### 设计要求
- 深色主题：背景 `#0a0a0a`，卡片背景 `#1e1e1e`，文字 `#e0e0e0`。
- 输入框背景 `#2d2d2d`，边框 `#404040`。
- 生成按钮使用渐变（`from-blue-600 to-purple-600`），hover 效果。
- 参数滑块样式统一（可使用 Tailwind 自定义 range）。
- 历史记录项 hover 高亮，删除按钮红色。
- 输出区域最大高度限制，自动滚动到底部。

### 注意事项
- **流式解析**：确保正确处理 `data: [DONE]` 和多行数据块，避免 UI 卡顿。
- **并发控制**：生成过程中禁用“生成内容”按钮，并显示加载动画，防止重复请求。
- **错误处理**：API 调用失败时应恢复按钮状态，显示错误提示（如“生成失败，请检查网络或 API Key”）。
- **长文本性能**：流式更新时只更新输出面板的内容，避免整个页面重渲染。
- **历史记录去重**：每次生成保存时，不应重复保存相同的记录（可通过比较内容等，但简单按时间保存即可）。
- **清空历史时**：需同时清空 localStorage 和组件状态。
- **提示词优化**：调用优化接口时也要显示加载状态，避免用户重复点击。

### 扩展思路（后续可选）
- 添加自定义模板功能（用户可保存自己的提示词模板）。
- 支持多版本生成（一次请求生成 3 个不同结果）。
- 集成文本对比工具（diff 视图）。
- 支持导出生成结果为 Markdown 或 PDF 文件。
- 添加多语言翻译模式（基于现有模式的扩展）。

## 四、优化后的提示词模板（30年编辑经验版）

> 以下为 `promptTemplates.ts` 中每个模式应使用的完整提示词模板。用户输入通过 `{用户输入}` 占位符传入。可根据需要附加“通用优化原则”。

### 1. 文章续写（保持风格与逻辑连贯）

```
请根据上文续写文章。要求：
- 严格保持上文的语气、节奏、视角（第一/第三人称）和用词习惯
- 段落之间逻辑紧密，无明显跳跃
- 若上文包含特定修辞手法（如比喻、排比），请延续使用
- 续写部分自然过渡，结尾可留有悬念或段落小结
- 总续写长度控制在 [200-500] 字之间（可配置）

上文内容：
"""
{用户输入}
"""
```

### 2. 内容改写（提升专业度与可读性）

```
请对以下文本进行专业级改写。要求：
- 纠正语法错误，优化句式结构（避免过长从句）
- 提升用词精准度：去除口语化表达，替换为更正式/专业的同义词（根据下文[目标场景]调整）
- 保持核心信息不变，不得增删事实性内容
- 输出时附上“改写说明”：列出3处主要改动及原因（可选）

目标场景：[正式报告 / 营销文案 / 学术摘要 / 技术文档]
原始文本：
"""
{用户输入}
"""
```

### 3. 内容扩展（增加深度与例证）

```
请扩展以下文本，使其更丰满、有说服力。扩展要求：
- 每段核心论点后增加1-2个具体例子或数据支撑（如无可信数据，可用“例如”打头的一般例证）
- 增加过渡句，使段落衔接更自然
- 若原文有观点无论证，请补充“为什么”的解释
- 总字数扩展至原始字数的 [150% – 200%]
- 扩展后附上“新增内容摘要”，用列表形式标出主要添加点

原始文本：
"""
{用户输入}
"""
```

### 4. 内容总结（提取核心与结构化输出）

```
请对以下文本做多层级总结。输出格式必须为：
# 核心结论（一句话）
- 要点1：{概括+支持性细节（≤20字）}
- 要点2：...
- 要点3：...

# 关键数据/引用（如有）
- {数据1}
- {数据2}

# 行动建议或后续步骤（针对决策类文本）
- ...

原文：
"""
{用户输入}
"""
```

### 5. 邮件撰写（情境化与礼貌等级）

```
请写一封邮件。要求：
- 收件人关系：[内部同事 / 客户 / 上级 / 陌生合作方]（据此决定称呼、敬语、语气）
- 目的明确：首段点明写信意图
- 结构：问候 → 背景/事由 → 具体请求或信息 → 礼貌结尾（含期待回复）
- 长度：不超过200字（不含签名）
- 附上“语气评分”：指出哪些句子可能显得生硬，并提供温和替代版

邮件主题：{用户提供}
补充信息或要点：
"""
{用户输入}
"""
```

### 6. 文案生成（营销导向与A/B测试意识）

```
请为以下产品生成营销文案。要求：
- 产品定位：{高端/性价比/创新/环保...}
- 目标人群画像：{年龄、痛点、喜好}
- 输出两个版本：版本A（理性说服型，列出功能与数据）；版本B（情感共鸣型，讲故事或激发渴望）
- 每个版本长度：50-80字，适合社交媒体（如朋友圈、微博）
- 结尾附带互动引导（如“点击下方了解详情”或“你更看重哪个功能？评论区告诉我们”）

产品/服务信息：
"""
{用户输入}
"""
```

### 附：通用优化原则（可组合使用）

用户在使用以上模板时，可额外附加以下指令以进一步精细控制：

- **读者水平**：“面向初中生/大学生/专家，避免术语/解释术语”
- **情感基调**：“保持客观中立 / 适度热情 / 略带紧迫感”
- **格式要求**：“每段不超过4行 / 使用Markdown小标题 / 关键句加粗”
- **避免事项**：“不要使用陈词滥调（如‘在当今时代’） / 禁止第一人称”
